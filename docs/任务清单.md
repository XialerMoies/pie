## 长期 Agent 引擎路线（触发式）

### 已确认决策

- **短期继续使用 PI**：只跟进选定的稳定版本和安全修复，不追逐每个上游版本。
- **fork 保持薄**：只保留少量、可单独测试、能按行为重放的补丁；不把深度魔改继续堆入 PI fork。
- **不做深 fork**：它既承受高频上游冲突，又无法获得真正独立的架构边界，长期成本最高。
- **深度定制进入自有引擎**：E1 触发后，新的执行循环、事件协议、会话策略和编排能力进入 `NativeAgentEngine`；触发前不为预想中的定制提前建设第二套运行时。

### Phase E0：建立 AgentEngine 防腐层

**目标：** 服务端、主 Agent 和子 Agent 不再直接依赖 PI 的 `AgentSession`、`ModelRuntime` 和 `SessionManager`。

**E0-a（已完成）：** 已定义 `AgentEngine`、版本化 `AgentEvent`、`EngineUsage`、`EngineContextUsage`、模型能力、错误、取消和 compaction 语义，并由现有 PI 路径提供实现；没有编写原生 Agent 循环。

**E0-b（自定义模型厂商之后）：** 将剩余 PI 接入收口到 `PiAgentEngine`，完成主会话、子 Agent、设置页和 SSE 的适配迁移。

**usage 契约边界：**

- `ProviderUsage` 表示单次 provider 请求返回的原始 input、output 和 cache 计量。
- `ContextUsageSnapshot` 表示当前上下文占用及 `exact`、`mixed`、`estimated` 来源。
- `CostLedger` 只消费 `ProviderUsage` 与 `PriceCatalog` 生成金额和预算记录，不扫描会话文件，也不重新计算 Token。
- `PiAgentEngine` 与未来的 `NativeAgentEngine` 必须提供相同契约，不能各自定义一套 usage 语义。

**完成标准：**

- 定义项目自己的 `AgentEngine`、`AgentEvent`、会话、模型和 usage 契约。
- 现有 PI 接入收口为 `PiAgentEngine`，行为保持不变。
- PI SDK 的直接 import 只允许出现在适配器和 SDK 合约测试中，并有结构门禁。
- 主会话、子 Agent、设置页和 SSE 通过项目契约访问引擎。

**实现记录：**

- `src/agent-engine/contracts.ts` 固化事件、usage、模型能力、错误和终止状态。
- `src/agent-engine/pi-adapter.ts` 是当前唯一 PI 运行时适配边界。
- `src/server/server-context.ts` 将 core/security/storage/providers/infra 分组，`http-app.ts` 与 `server-lifecycle.ts` 分离 HTTP 和生命周期职责。
- 前端已删除 `window.__state`、`window.__tabs` 和 `__uiStateStore` 旧投影，运行态由 typed store/facade 持有。
- 权限拒绝通过统一 failure envelope 传递；危险操作和确认通道不可用均保持 fail-closed，并提供结构化中文恢复反馈。

### Phase E1：NativeAgentEngine MVP

**范围：** prompt、模型流、工具调用循环、steer、follow-up、abort、事件发布和 usage 汇总。

**原则：** 第一版只覆盖已验证的核心工作流，不同时重写全部 Provider、OAuth 和模型目录；复用现有 ToolRegistry、权限系统、MCP 和子 Agent supervisor。

### Phase E2：会话与压缩独立

- 实现新建、打开、恢复和持久化会话。
- 实现上下文组装、统一 usage 接入、压缩和失败恢复。
- 使用录制事件和历史 JSONL 做兼容回放，覆盖迁移和受损会话。

### Phase E3：Provider 层逐步独立

- 定义稳定的 `ProviderDriver`，优先覆盖 DeepSeek 和 OpenAI-compatible。
- 按真实使用量迁移认证、模型目录和更多 Provider，不追求一次性全部覆盖。
- 完成迁移前，PI Provider 适配器仍作为可回退实现。

### 默认切换门槛

- 文本流、工具调用、中止、模型切换、会话恢复、压缩和子 Agent 全部通过契约测试。
- 事件顺序、usage、权限和失败语义不弱于 `PiAgentEngine`。
- 安全检查继续由宿主 Tool/权限层强制执行，模型和引擎不可绕过。
- 手工完成至少 20 次真实工程任务，并连续 4 周没有阻断级数据损坏或权限回归。
- 切换后仍保留一个发布周期的 PI 回退开关。

### 维护触发条件

- PI 稳定版本升级连续两次各消耗超过 2 个工作日，提前推进 E1。
- fork 行为补丁超过 5 个，或单次升级需要解决大面积冲突，停止增加 fork 补丁并转移到原生引擎。
- 已验证的重要产品能力被 PI 架构明确阻塞，且无法通过 E0 适配层以可控成本实现时，可将 E1 提升为阶段主线。
- 原生引擎未达到切换门槛前，不为了“拥有自己的引擎”牺牲当前可用性。
- 未触发上述条件时，E1～E3 保持未启动；一旦触发，则成为有明确里程碑的阶段主线，不与功能主线长期并行。

## 产品定位

**my-code-agent 是安全、可编排、可持续积累能力的桌面工程助手。**

- 首先服务软件工程，不转型为覆盖聊天渠道、日程和生活自动化的泛个人助手。
- 外部 agent 是可选能力提供者，不是固定的“下级”。
- 新能力必须可关闭、可审查、可测试、可回滚。
- “可持续积累”必须同时包含存储与验证，不能只增加记忆数量。

## 能力分层

```text
Tool：执行原子操作
Skill：完成某类任务的方法和流程
Agent：可被调度的角色、上下文与责任边界
Provider：本地模型或外部 agent 的执行来源
```

- 自定义 Agent 可以配置默认 Skill。
- Skill 可以声明所需 Tool，但不能扩张 Agent 的工具权限。
- Provider 不决定上下级关系，只提供能力、模型和成本选项。

- 用户级记忆使用 `<PI_USER_CONFIG>/memory`，工作区级记忆使用 `<workspace-root>/agent/memory`；会话级记忆不落盘。
- `read_memory` / `write_memory` 支持 `scope=user|workspace`，并增加 `list_memory`、`delete_memory`、`set_memory_enabled`。
- `memory-index.json` 保存来源、作用域、时间、启用状态、摘要和 `traceId`；`MEMORY.md` 只作为索引。
- prompt 只注入启用索引，工作区同名条目覆盖用户级视图，正文按需读取。
- 旧 `<APP_ROOT>/data/pi/memory` 仅在首次 memory 操作时懒迁移到用户级目录，冲突不覆盖。
- 已验证：`npm run typecheck`、`npm run capabilities:check`、memory/prompt/tool focused tests 通过；全量回归已完成，剩余环境缺失的 TypeScript 依赖已补齐并单独复验通过。

## Checkpoint A：学习闭环与价值复核

Task 1～3 完成后先验证是否真的“越用越好用”，不立即进入高成本编排功能。

```text
技能或记忆被使用
  -> 记录来源与结果
  -> 用户保留、修正或禁用
  -> 比较后续命中与失败
  -> 生成技能或记忆草稿
  -> 人工审核后升级
```

**本地验证信号：**

- 技能在至少 3 个不同任务中被重复使用。
- 用户没有立即关闭或大幅重写该技能。
- 启用后产出被保留，测试或手工验收通过。
- 长期记忆至少 3 次正确命中，并减少重复说明。
- 错误记忆能够被发现、修正、追溯和回滚。

**未达到信号：** 暂缓第二阶段，继续修正技能选择、记忆作用域和用户控制，不用增加更多自动化。

## 第二阶段：长生命周期编排（Checkpoint A 通过后）

### Task 4：CostLedger 与预算护栏

**目标：** 在延长子 agent 生命周期前，建立独立成本账本、预算上限和原子中止。

**完成标准：**

- CostLedger 独立于 usage-index。
- CostLedger 只消费统一的 `ProviderUsage` 与 `PriceCatalog`，不扫描 session，也不另建 Token 计算口径。
- 支持 provider/model 输入、输出、cache 价格和计费单位。
- 主 agent 与全部子 agent usage 可以汇总。
- 未知价格明确显示“未知”，不伪造金额。
- 启动前显示成本预估；运行中显示已花费与上限。
- 到达上限后原子中止，不再启动新子任务。

**为什么做：** 长生命周期和多 agent 会放大成本，预算护栏必须先于 continuable 和会议模式。

### Task 5：Continuable subagent

**现状修正：** 只读 fan-out、worker 进程、delegate_tasks、自定义 Agent、并发限制和 usage 汇总已经完成；不再重复建设子 agent MVP。

**目标：** 让现有 one-shot 子 agent 可以继续、恢复和被主 agent 控制。

**完成标准：**

- 支持 `send`、`status`、`abort`、`resume`。
- 子任务描述、事件和结果可以持久化并冷恢复。
- 权限、预算、并发、最大轮数和最大工具调用仍由 supervisor 强制执行。
- 主会话可以查看连续事件、当前状态和最终汇总。
- 父进程退出时能可靠结束或安全保存子进程状态。

### Task 6：会议 / judge panel

**目标：** 在高风险架构决策、评审和方案比较时，允许主 agent 组织多个角色评审并收敛结果。

**依赖：** CostLedger 和 Continuable subagent 完成。

**完成标准：**

- 会议只由用户按需发起，不默认开启。
- 支持不对称模型配置：强主导模型加廉价评审模型。
- 发起前展示预算和参与者，用户确认后运行。
- 评审意见、反驳和最终结论可追溯。
- 达到预算、轮数或时间上限后自动收敛或中止。

## 值得验证的方向

这些功能不承诺进入正式架构，每项先通过独立原型回答关键问题。

### V1：ACP 外部 agent provider

只接一个 provider，验证启动、消息、流式事件、中止、进程树清理、权限和 usage。成功后它作为可选 Provider 进入现有编排，不把本项目降为调度外壳。

### V2：Windows 受限执行环境

独立验证普通用户权限、Electron spawn、PowerShell、Git、npm、管道输出、大工作区 ACL 传播、清理和性能。

- 它只补充写侧隔离，不能替代现有命令语义安全和路径治理。
- 必须单独实现 sandbox fail-closed：请求隔离但不可用时执行 `SANDBOX_UNAVAILABLE -> refuse`。
- 验证完成前不接入默认命令链。

### V3：Agent 代码导航工具

基于现有 tsserver 增加 definition、references、hover 等只读工具。先支持 TypeScript/JavaScript；只有实测能减少全文搜索和误读，才扩展更多语言。

### V4：运行态感知与元素定位

分阶段验证：

1. 捕获 dev server stdout/stderr，形成有界日志和错误事件。
2. 通过 Electron CDP 捕获 console error 和 network failure。
3. 用户点击问题元素，将 DOM 快照和批注作为 attachment 发送给 agent。
4. 视觉截图分析只在可用模型下启用，不作为前置条件。

观察默认采用只读；导航、点击和执行操作继续经过权限确认。

### V5：工程型后台任务

只验证测试、构建、索引等工程 job，以及完成通知、查看输出和中止。验证稳定后再讨论定时调度；不扩展成通用生活提醒系统。

### V6：增量事件投影

只为新事件增加统一 envelope、持久化规则和 projection 测试，逐步减少运行时状态与日志不一致。不一次性替换 JSONL、chatStream、SSE 和 AppEventHub。

### V7：最小插件接缝

旧 backlog 把插件系统列为“下一阶段主线”，该优先级已失效。只有出现至少两个真实扩展需要共享安装、生命周期、权限和 UI 注册机制时，才设计最小插件 API；优先复用 ToolRegistry、MCP、Skill 和 registerPane，不引入大型插件框架。

## 观察项

### O1：单窗口单项目多会话并发（④-C）

观察窗口：完成 Task 1～5 后的 4 周或 20 次真实开发任务。

只有出现至少 3 次以下情况才重新立项：用户确实需要在同一工作区维护两个独立主对话，而且多窗口、运行中补充和主 agent 委托都无法替代。

未达到条件时移入“暂不计划”，不长期悬挂。

### O2：定时调度与工作流

只有 V5 工程型后台任务被稳定使用，并出现重复的定时工程任务时再评估。第一版只能调度受权限和预算控制的工程 job。

## 暂不计划

| 功能 | 原因 |
|---|---|
| 泛个人助手和多聊天渠道 | 偏离工程工作台优势，身份、渠道和生活服务均需重新建设 |
| 固定“主人 agent / 下级编码工具”层级 | 外部 agent 应按任务能力参与，不由品牌决定层级 |
| 未经审核自动安装或永久启用技能 | 会固化错误经验，并引入提示注入和供应链风险；只允许生成待审核草稿 |
| 全面事件溯源重构 | 改动面和回归风险过高；采用 V6 渐进收敛 |
| 直接照搬 dsh Windows ACL sandbox | 当前实现是 partial，存在 ACL 残留、传播成本和管道限制；只做 V2 验证 |
| 每包 100% 覆盖率 | 单人项目维护成本过高；继续按安全和风险分配测试密度 |
| 为插件化全面拆包或引入 Cordis | 当前模块边界已可控，没有对应收益 |
| AI 安全分类器自动审批 | 不用概率模型替代现有确定性安全规则；未来最多作为提示信号 |
| 向量索引 / Meilisearch | 当前全文搜索和项目规模未证明需要额外索引基础设施 |
| 自动根据拒绝记录修改系统提示 | 容易把偶然拒绝固化成长期行为；先纳入本地学习信号观察 |
| SSH、社交、移动 VM 功能大包 | 没有明确用户需求；需要时优先以受限 Tool、MCP 或独立扩展验证 |
