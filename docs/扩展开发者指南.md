# 扩展开发者指南（第一阶段）

## 这是什么

第一阶段提供的是**声明式扩展管理**：扩展作者提交 package manifest，用户可以校验、安装、信任、启用、停用和卸载它；宿主保存来源、指纹、信任状态和安全的非敏感设置。

它不是任意代码加载器。当前不会下载、导入或执行第三方 `entry`，也不会把 `AgentRuntime`、服务端上下文、Electron、密钥或安全存储交给扩展。`entry`、隔离方式、权限和资源限额均是供宿主审计与后续受控执行阶段使用的声明。

## 快速开始

从 [extension-manifest.example.json](./extension-manifest.example.json) 复制一份清单，再运行：

```powershell
npm run extensions -- validate --manifest ./manifest.json
```

校验只读取清单，不安装、不信任、不执行入口脚本，也不创建组件或扩展状态。成功时会输出标题、作者、贡献点、权限、Agent 限额、设置项和兼容性。

安装命令仍会再次校验清单。这是持久化边界的防御性校验，不是要求用户先在桌面端做一次重复预检。

## Manifest 契约

清单根字段：

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| `schemaVersion` | 固定为 `1` | 清单版本。 |
| `packageId` / `packageVersion` | 稳定小写 ID / 数字版本 | `packageVersion` 必须与 `component.version` 相同。 |
| `component` | 必填对象 | 产品贡献的身份、显示名、贡献类型、限额和设置。 |
| `entry` | 可选安全相对路径 | 当前不执行；不得为绝对路径或包含 `..`。 |
| `source` | 必填对象 | 非内置包必须给出不可变 `origin` 与 SHA-256 `digest`。 |
| `signature` | 非内置包必填 | 目前验证形状，不进行公钥签名验真。 |
| `compatibility` | 必填对象 | `host`、`contract`，可选 `engine` 的受支持版本范围。 |
| `permissions` | 必填对象 | 审计声明，不直接授予运行权限。 |
| `resources` | 必填对象 | 最大内存，以及可选 CPU、网络、文件字节上限。 |
| `isolation` | 必填对象 | 预声明未来受控执行的隔离方式与限定入口。 |

`packageId`、组件 ID、设置 ID、来源 `keyId` 均使用小写字母、数字、`.`、`_`、`-`，且以字母或数字开头。包版本只接受 `1`、`1.0`、`1.0.0` 这类数字版本。

### 组件字段

`component` 的关键字段如下：

| 字段 | 要求 |
| --- | --- |
| `id` | 稳定的组件 ID；若声明 `providedBy`，它必须等于 `packageId`。 |
| `kind` | 外部扩展只能是 `optional`。 |
| `capability` | 见下方贡献类型。 |
| `source` | registry 包填 `user`；必须与包来源映射一致。 |
| `displayName` / `publisher` | 可选的任意语言展示标题和作者名。 |
| `agentConfig` | 可选 `timeoutMs`（100 至 3,600,000）和 `maxConcurrent`（1 至 30）；由宿主强制。 |
| `settings` | 可选非敏感设置 schema，见下文。 |

### 贡献类型

| `component.capability` | 产品声明 | 第一阶段状态 |
| --- | --- | --- |
| `agent-tool` | Agent 工具 | 可登记；只有宿主受控贡献才可能进入 ToolPool。 |
| `desktop.ui-pane` | 桌面面板 | 可被第一方宿主声明；第三方入口当前不会执行。 |
| `desktop.language-service` | 桌面语言服务 | 可被第一方宿主声明；第三方入口当前不会执行。 |
| `server.route` / `model-adapter` | 服务端路由 / 模型协议 | 外部扩展直接拒绝，属于宿主边界。 |

产品层的 `ExtensionManifest` 用贡献点数组描述能力，但第一阶段的 package manifest 一次只能通过一个 `component.capability` 声明一类贡献。不能用多个 package 或清单字段绕过宿主边界；跨端、多贡献包属于后续受控执行阶段的设计项。

### 权限、限额和设置

- `permissions.filesystem` 只允许 `read`、`write`、`create`、`remove`；`network` 可为布尔值或允许的 HTTPS 地址列表；`subprocess` 为布尔值；`secrets` 为命名引用列表。
- 这些权限只用于审计、用户理解和未来宿主投影。真正执行时仍必经 permission、security、PathGuard、trace、abort 和事件终态链。
- `resources.maxMemoryMb` 必填，最大 4096；其他上限受宿主最大值约束。
- 设置可用类型为 `string`、`number`、`boolean`、`select`。`select` 必须提供非空且不重复的 `choices`。
- 设置 ID 不能包含 `secret`、`token`、`password`、`api-key`、`private-key` 等敏感含义。密码、令牌、连接密钥属于宿主安全存储，不属于 extension settings。
- 设置默认值由 manifest 给出，用户默认值与工作区覆盖值由宿主持久化，工作区优先；扩展回调只能获得不可变的已解析快照。

## 生命周期与信任

外部 package 的状态顺序是：

```text
install -> validate -> enable -> activate -> dispose -> uninstall
```

外部包安装后默认不受信任，不能激活。信任撤销、停用和卸载会先释放已登记资源；卸载会同时删除用户和所有已有工作区的扩展设置，包记录被删除，重启或同 ID 重装均不会复活旧状态。第一阶段不承诺热更新。

## 稳定诊断

`validate` 的失败输出固定包含：

```text
扩展校验失败
文件: <manifest 路径>
代码: <稳定错误代码>
原因: <可定位的字段或规则原因>
修复建议: <下一步>
```

退出码非零表示清单不能用于安装。作者可将该命令直接放入本地脚本或 CI。

## 第一阶段边界

第一阶段完成后，以下能力明确不做：第三方 JS 自动执行、动态下载、热重载、第三方路由/模型适配、worker/process IPC、崩溃隔离、市场、升级和依赖求解。用户级下载与更新属于第二阶段，必须先有来源完整性和更新回退验收；第三方可执行入口则额外必须先有受控执行沙箱与独立验收。

## 第二阶段预告：用户级扩展源

第二阶段首先计划提供的是**用户自管来源**，不是官方扩展市场。用户自行添加可信来源，宿主从这些来源读取受限扩展索引、比较版本并下载用户明确选定的包；安装、信任、启用、停用和卸载仍复用本指南的生命周期。

来源管理会保留来源 URL、身份指纹/公钥标识、刷新时间和用户信任状态。更新必须展示版本、来源和权限差异并等待用户确认；下载或校验失败时保留当前已安装版本。移除来源不会自动卸载已经安装的包。

第二阶段也不意味着开放任意代码执行：下载的包仍须通过 digest、兼容性和 manifest 校验，未信任包不能激活。第三方可执行入口仍需 worker/process 沙箱、IPC、资源限额和崩溃隔离后才会开放。

官方目录、账号体系、发布审核、公共搜索/推荐、评分、支付和官方背书不在该阶段范围内。

### P2-A0：本地扩展源试点

当前先支持用户登记本地 `file` 来源，不联网、不下载压缩包，也不提供市场页面。来源索引是声明数据，示例格式如下：

```json
{
  "schemaVersion": 1,
  "sourceId": "team.local",
  "packages": [{
    "packageId": "example.search",
    "displayName": "示例搜索",
    "publisher": "Example",
    "versions": [{
      "version": "1.0.0",
      "manifestPath": "packages/example.search/1.0.0/manifest.json",
      "manifestDigest": "<manifest 原文 SHA-256>",
      "manifestFingerprint": "<规范化 package manifest 指纹>"
    }]
  }]
}
```

`manifestPath` 必须是来源索引目录下的安全相对路径；浏览时宿主会重新读取原文，校验摘要、package 身份/版本、兼容性和规范化指纹。CLI 可使用：

```text
npm run extensions -- source-add team.local --path ./index.json
npm run extensions -- source-view team.local
npm run extensions -- source-install team.local example.search --version 1.0.0
npm run extensions -- source-remove team.local
```

来源安装仍是未信任声明，后续必须显式 trust/enable 才可能进入受控贡献点；来源移除不会卸载已安装包。manifest 的 `entry` 在此阶段永远不会被导入或执行。
