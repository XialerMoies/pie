# my-code-agent 能力组件插件化清单

> 盘点基线：2026-08-27。本文按当前源码中的注册表、运行时装配、路由、桌面端入口和前端挂载点整理；“建议形态”是目标边界，不代表对应能力已经完成插件化。

架构分层、依赖方向和统一术语以 [架构规范](./架构规范.md) 为准；本文只维护组件化判断和推进顺序。

## 1. 结论先行

项目适合走“稳定底座 + 受控必需组件 + 可选能力组件 + 声明式数据”的路线，不适合把每个类、路由或界面块都做成可热卸载插件。

- 可以高度插件化：普通 Agent 工具、MCP server、模型协议适配器、Skill、子 Agent 定义、业务侧栏、语言服务、诊断/展示附件。
- 可以替换但必须受控：AgentEngine、session store、model router、permission evaluator、security parser、ToolPresentation、MCP host、桌面宿主实现。
- 适合开放扩展点而非整体卸载：ToolRegistry/ToolPool、Prompt 组装、HTTP route registry、AppEventHub、设置页容器、窗口/面板容器。
- 不应交给普通插件：进程启动、preload/IPC 信任边界、权限与路径强制执行、事件/session 不变量、原子存储和锁、组件事务管理器本身。
- 不应伪装成插件：Profile、provider 配置、模型条目、memory 条目、MCP catalog 元数据等声明式数据。
- 不进入运行时组件系统：构建、测试、coverage、replay、评测、发布脚本。

当前的能力组件底座已经具备 manifest、信任/启用、依赖检查、Required 替换事务、generation/lease 和回滚框架；真实执行绑定已接通 `tool-presentation` 与 `model-router` 两个 Required Component。其余已登记的 Required Component 仍需先定义窄宿主接口，不能仅因出现在 catalog 中就宣称可替换。

## 2. 分类与边界

### 2.1 建议形态

| 等级 | 含义 | 管理规则 |
|---|---|---|
| K：最小底座 | 启动、隔离、组件装载和安全仲裁所需的最小物理代码 | 不支持运行时卸载；底座上层实现仍可由 Required Component 替换 |
| R：必需组件 | 系统闭环必须始终有一个健康实现的能力 | 只能通过隔离预检、用户批准、原子切换、generation 固定和失败回滚替换 |
| O：可选组件 | 缺失时系统仍能以较小能力集运行 | 可独立安装、信任、启用、停用和卸载 |
| C：扩展点 | 宿主保留 registry/container/protocol，第三方贡献实现 | 贡献项可插拔，扩展点本身属于 K 或 R |
| I：内部模块 | 仅用于拆分实现，没有独立产品生命周期 | 保持普通模块；除非出现多个成熟实现，不建立插件协议 |
| D：开发基础设施 | 测试、构建、生成、发布和诊断脚本 | 不进入生产运行时组件系统 |

### 2.2 生效时机

| 边界 | 适用范围 |
|---|---|
| 热启停 | 无持久运行资源或能可靠 `dispose` 的可选工具、UI 贡献、数据型能力 |
| 下个请求 | 仅改变当前 session 下一轮工具/提示词投影，且不破坏已进行中的工具调用 |
| 下个 session | AgentEngine、Profile 组合、模型路由等需要固定 generation 的能力 |
| 页面重载/窗口重建 | Monaco、主要聊天视图、窗口布局等前端宿主能力 |
| 进程重启 | Electron 宿主、preload、IPC、server binding、底层存储/安全服务 |
| 应用升级 | 最小启动器、组件加载器、签名/信任根和迁移框架自身 |

## 3. 最小底座与已登记必需组件

### 3.1 最小底座

| 功能/组件 | 当前实现 | 建议 | 边界 | 判断 |
|---|---|---|---|---|
| 可执行程序启动与故障兜底 | Electron/CLI bootstrap、server bootstrap | K | 应用升级 | 必须先存在，才能加载任何组件 |
| 组件目录与生命周期仲裁 | `CapabilityComponentManager` | K | 应用升级 | 组件不能负责替换管理器自身，否则无法保证事务和回滚 |
| 组件信任、依赖图、generation/lease | capability component 与 replacement 模块 | K | 应用升级 | 是所有 R/O 组件共同依赖的治理平面 |
| 最小配置、数据目录和原子锁 | data layout、root config、file lock、locked JSON store | K | 进程重启/升级 | 缺失会使组件状态、回滚和迁移都不可信 |
| preload/IPC 校验和桌面 session token | Electron preload、IPC、HTTP bootstrap 安全 | K | 进程重启/升级 | 属于进程间信任边界，不能由未受信插件覆盖 |
| 强制事件/session 不变量 | AgentEngine invariants、事件 envelope、replay 基线 | K/R 宿主契约 | 应用升级 | 允许替换实现，不允许替换者改变协议不变量 |

### 3.2 当前 `REQUIRED_COMPONENT_MANIFESTS`

| ID | 当前职责 | 建议形态 | 建议替换边界 | 当前落地程度 |
|---|---|---|---|---|
| `bootstrap-kernel` | 最小宿主生命周期契约 | R，物理启动器仍为 K | 进程重启 | 已登记；尚未形成可执行 binding |
| `session-store` | session 持久化、恢复、fork/replay | R | 下个 session 或进程重启 | 已登记；需定义存储/迁移/事务接口 |
| `model-router` | provider/model 发现、选择和稳定运行时 | R | 下个 session | 已接通真实 runtime provider binding；主 Agent、子 Agent、设置路由和模型同步均通过 session lease 固定的 router generation |
| `permission-evaluator` | permission mode、规则、确认、审计决策 | R | 进程重启，或无在途请求时切换 | 已登记；安全关键，需影子验证和 fail-closed |
| `security-parser` | 命令解析、危险命令和只读分类输入 | R | 进程重启，或隔离验证后切换 | 已登记；必须保留统一 `SecurityParseResult` 与 shadow/failure matrix |
| `tool-presentation` | `AgentTool` 到具体 AgentEngine 工具协议的呈现 | R + C | 下个 session；旧 session 固定旧 generation | 已登记且已接通真实 runtime provider binding |
| `mcp-host-integration` | MCP discovery、trust、连接、ToolPool 投影 | R | 下个 session/进程重启 | 已登记；尚未形成完整可执行 binding |

## 4. Agent 与运行时

| 功能/组件 | 当前能力 | 建议形态 | 生效边界 | 说明 |
|---|---|---|---|---|
| `AgentEngine` / `PiAgentEngine` | 创建主 Agent/子 Agent、发送消息、事件归一化、模型接入 | R + C | 下个 session/进程重启 | PI 是当前实现；未来 Native 或其他引擎实现同一宿主契约 |
| `AgentRuntime` | session 生命周期、MCP、上下文、宿主能力转发 | R 内部编排 | 下个 session | 先继续拆成窄接口，不把整个大对象直接暴露给插件 |
| 主 Agent 定义 | Profile、工具投影、提示词和模型组合 | O 声明式 Agent 组件 | 下个 session | “Agent 是组件”应指受治理的组合定义，不是复制一套宿主内核 |
| ToolRegistry | 原生工具注册、名称唯一性和转换入口 | C，registry 属于 K/R | 启动/受控注册 | 工具可插拔，注册表不能被普通工具替换 |
| ToolPool | native/MCP 工具合并、受众和 feature gate 投影 | C，宿主持有 | 下个请求/session | 负责能力投影，不能让插件绕过 Profile 和依赖检查 |
| ToolPresentation | canonical execute 包装、PI adapter、session 工具呈现 | R + C | 下个 session | 当前首个真实 Required binding；permission/security/trace/abort 包装仍由宿主强制持有 |
| Prompt 组装 | 基础提示、Profile sections、Skill 内容、证据契约 | C | 下个请求/session | 允许贡献 prompt section；身份、安全和宿主契约段不可被覆盖 |
| Agent Profile | `standard`、`minimal`，投影工具/提示词/feature gates/MCP/Skills | 声明式受管组件，不是任意代码插件 | 下个 session；安全切换可在步骤边界 | `standard` 全能力；`minimal` 仅 command、编辑和 plan 工具，feature gate 仅 planning |
| Feature gates | `web`、`memory`、`delegation`、`skills`、`planning`、`mcp` | C 的统一投影维度 | 下个请求/session | 不与 PermissionMode 混用 |
| EvidenceContract / fact verification | 请求级证据来源限制、缺失字段语义 | 宿主策略，不独立插件化 | 单次请求 | 应融合进各 Profile；不能成为可绕过安全边界的“事实核验插件” |
| 规划生命周期 | active/pending/committed/cancelled、replay/fork | R 内部状态机 + O 命令/UI 贡献 | 步骤边界 | 状态机由宿主持有，`enter/exit_plan_mode` 只是入口 |
| 上下文/token 统计 | 上下文窗口和用量归一化 | I，展示层可 C | 热更新 | 未来可插入不同计费/统计 provider，但当前无独立生命周期收益 |
| trace、结果归一化、abort | 工具执行证据链和统一终态 | K/R 契约 | 不允许运行中替换 | 所有工具组件必须经过，插件不可自报成功绕过终态 |

## 5. Agent 工具清单

当前 `src/agent/tools/index.ts` 注册 21 个工具；`file-diff.ts` 是前端/内部差异展示支持，未注册为 Agent 工具。

| 工具 | 功能 | 建议形态 | 程度与依赖 |
|---|---|---|---|
| `git-status` | 读取仓库状态 | O 单工具 | 可热启停；依赖工作区授权和 Git 可用性 |
| `search` | 工作区文本搜索 | O 单工具 | 可热启停；路径访问仍由宿主管理 |
| `file_read` | 读取文件正文和证据 | O 基础工具 | 可热启停；依赖 RootRegistry/PathGuard/trace |
| `explorer_list` | 浏览目录 | O 基础工具 | 可热启停；不得绕过路径授权 |
| `git_log` | 读取提交历史 | O 单工具 | 可热启停 |
| `file_outline` | 提取文件结构 | O 单工具 | 可热启停；解析器可作为内部 provider |
| `web-search` | 网络搜索 | O 单工具 + C backend | 可热启停；搜索 backend 可替换 |
| `web-fetch` | 获取网页内容 | O 单工具 | 可热启停；网络策略、超时和重定向限制由宿主持有 |
| `command` | 执行 Shell 命令 | O 高风险工具 | 可从 Profile 移除；执行时必须依赖 R security parser、permission evaluator、PathGuard，不能自行接管安全层 |
| `write_agent_md` | 写入 Agent 指令文件 | O 单工具 | 可热启停；仍受写入授权和冲突保护 |
| `read_memory` | 读取记忆 | O memory 工具包 | 与 memory backend 配套；作用域和证据字段由宿主规范 |
| `write_memory` | 写入记忆 | O memory 工具包 | 写操作受权限、锁和审计约束 |
| `list_memory` | 列出记忆 | O memory 工具包 | 可按 Profile 投影 |
| `delete_memory` | 删除记忆 | O memory 工具包 | 破坏性操作需确认/授权 |
| `set_memory_enabled` | 启停记忆条目 | O memory 工具包 | 条目是数据，不应被当成代码插件 |
| `str_replace_editor` | 精确文本编辑 | O 基础编辑工具 | 可热启停；依赖文件授权、冲突检测和 trace |
| `file_write` | 创建/覆盖文件 | O 基础编辑工具 | 可热启停；写入安全边界仍归宿主 |
| `delegate_tasks` | 创建和协调子 Agent 任务 | O delegation 工具 | 依赖 subagent supervisor、资源上限和父任务所有权 |
| `skill_facts` | 读取 Skill trust/enabled/parse 等状态事实 | O skills 工具 | 依赖 Skill host；不能替代 Skill 信任管理 |
| `enter_plan_mode` | 进入规划生命周期 | O planning 工具 | 依赖宿主 plan state；不改变 permission mode |
| `exit_plan_mode` | 提交/退出规划生命周期 | O planning 工具 | 必须保留用户批准、取消和 replay 语义 |
| MCP 动态工具 | 来自已连接 server 的工具集合 | O server 的子贡献 | 随 MCP server 启停；不把每个动态工具当作独立安装包 |

工具插件化目标应是“工具包可注册并受 Profile 投影”，不是允许插件绕开 `ToolRegistry -> ToolPool -> ToolPresentation -> canonical execute` 链路。

## 6. 模型与 Provider

| 功能/组件 | 当前能力 | 建议形态 | 生效边界 | 判断 |
|---|---|---|---|---|
| Model Router / runtime coordinator | 模型列表、选择、刷新、稳定 session、切换协调 | R | 下个 session | 系统必须始终有一个可用路由实现 |
| PI provider adapter | 把自定义 provider 接入 PI | 当前 AgentEngine 的 R 内部适配器 | 下个 session | 换 AgentEngine 时应由对应 engine adapter 提供 |
| 六种协议 adapter | OpenAI Completions/Responses、Anthropic Messages、Mistral Conversations、Azure OpenAI Responses、PI Messages | O 协议组件 | 下个 session | 高价值插件点；共享认证、网络和错误规范 |
| 自定义 Provider 管理 | 创建、编辑、验证、删除 provider | C 服务 + UI 贡献 | 保存后/下个 session | 管理面可扩展，但引用检查和删除锁归宿主 |
| 单个 Provider 配置 | base URL、认证方式、模型等 | 声明式数据 | 保存后 | 不是代码插件，不需要独立 loader |
| 单个模型定义 | ID、能力、上下文窗口、价格/元数据 | 声明式数据 | 刷新后 | 由 model catalog/provider 提供 |
| bundled model metadata | 内置模型元数据 | 可替换数据目录 | 应用升级/刷新 | 不必包装为运行时插件 |
| credential/reference lock | 密钥读取、引用保护、稳定变更 | K/R 安全服务 | 进程重启 | Provider 插件只能请求凭据句柄，不能枚举其他密钥 |
| provider network client | 认证头、超时、响应处理 | R/C 网络执行层 | 下个 session | 协议插件贡献编码/解码，宿主保留网络政策 |

## 7. MCP、Skill、Memory 与子 Agent

### 7.1 MCP

| 功能/组件 | 建议形态 | 生效边界 | 判断 |
|---|---|---|---|
| MCP host/discovery/trust/tool adaptation | R + C | 下个 session/进程重启 | 支持 stdio、Streamable HTTP、SSE；统一连接、generation、缓存和 ToolPool 投影 |
| 每个已配置 MCP server | O | 下个请求/session | 独立安装、信任、启停、卸载和 health；其进程/连接必须可 dispose |
| MCP server 暴露的每个 tool | server 子贡献 | 随 server | 不单独安装，仍经过 ToolPresentation、permission、trace 和 abort |
| workspace `.mcp.json` / global `mcp.json` | 配置数据 | 重连后 | 保留兼容读取，逐步映射到组件 manifest |
| MCP trust store | K/R 安全数据服务 | 重新信任后 | 命令、参数、环境、cwd、transport/url 变化应使旧信任失效 |
| MCP 管理面板 | O UI 组件 | 热挂载 | 只是管理界面，不拥有底层信任决策 |
| 内置精选目录 | 元数据目录 | 刷新后 | 当前 9 项：filesystem、github、postgres、sqlite、duckduckgo、brave-search、docker、memory、sequential-thinking |

### 7.2 Skill

| 功能/组件 | 建议形态 | 生效边界 | 判断 |
|---|---|---|---|
| Skill parser/scanner/service/state store | R/C host service | 下个请求/session | 负责解析、来源、trust/enabled/parse 和提示词投影 |
| 单个 Skill | O 声明式组件 | 下个请求/session | 可安装、信任、启停、删除；正文是指令资源，不是宿主可执行代码 |
| Skill 管理设置页 | O UI 贡献 | 热挂载 | 通过宿主 API 管理，不能直接修改 trust 数据库 |

### 7.3 Memory

| 功能/组件 | 建议形态 | 生效边界 | 判断 |
|---|---|---|---|
| Memory backend/store | R 或 O provider | 下个 session/进程重启 | 若 Profile 不需要记忆可整体关闭；启用时必须有可靠 store 实现 |
| user/workspace memory 条目 | 受管数据 | 下个请求 | 不是插件；具备 scope、enabled、source 和正文证据 |
| 五个 memory Agent 工具 | O 工具包 | 下个请求/session | 统一启停比逐工具安装更符合使用语义 |

|---|---|---|---|
| subagent supervisor/delegation host | O host capability + C | 下个 session | 仅在 delegation feature 启用时需要；负责并发、取消、父任务所有权和资源上限 |

| git | status/diff/log/commit/push/pull | O service contribution | 可整体关闭；命令执行仍走宿主安全策略 |
| TypeScript | diagnostics、completion、quick info、definition、references、code actions | O language-service contribution | 将 TS 作为首个语言 provider，而非硬编码所有语言 |
| settings | auth、models/providers、preferences、layout、skills、storage、subagents、thinking | C 聚合路由 | 子域可贡献，认证/存储安全由宿主保留 |
| UI state | tab/layout/恢复状态 | R UI-state service | 数据服务，不等于 UI 插件本身 |
| permissions | mode、rules、audit | R 安全管理 route | 只能由可信宿主贡献 |
| diagnostics | 健康、运行诊断 | O/C | 可扩展诊断项，基础 health endpoint 保留 |
| components | 组件 catalog、状态和生命周期 | K/R 管理 route | 需要最高信任等级，普通 Agent/插件只读或无权访问 |

路由插件化应先把当前固定 `handlers[]` 变成带 ID、prefix、权限声明、body limit 和 dispose 的受控贡献注册表；在此之前，不加载任意第三方 route 代码。

## 9. Electron 桌面宿主

| 功能/组件 | 当前能力 | 建议形态 | 生效边界 | 判断 |
|---|---|---|---|---|
| desktop bootstrap/main/launch coordinator | 单实例、启动、参数和窗口协调 | K + R desktop host | 进程重启 | 可替换上层 desktop host，物理入口仍必须保留 |
| WindowManager/window partition | 多窗口、workspace 所有权、隔离分区、恢复 | R + C | 窗口重建/进程重启 | 允许窗口类型贡献，不允许插件任意共享 partition |
| server binding | `none`、`external`、`owned` 服务绑定策略 | R strategy/C | 进程重启 | 策略可替换，端口/所有权/退出协议由宿主管理 |
| preload/desktop IPC | 文件选择、窗口控制、桌面 token 等桥接 | K | 应用升级/进程重启 | 只暴露版本化、最小权限 API；UI 插件不得注入 preload |
| quit coordinator | renderer/server/child process 有界退出 | K/R | 进程重启 | 保证锁和子进程清理，不适合热替换 |
| HTTP client/dashboard navigator | 导航、健康等待、页面加载 | I/R desktop service | 窗口重建 | 有多个宿主实现后再提取插件协议 |
| CLI terminal | 从桌面启动 CLI/终端 | O desktop component | 热启停/窗口级 | 不影响桌面主闭环 |
| 崩溃恢复与多实例治理 | 进程、窗口和 workspace lock 竞争处理 | K/R | 进程重启 | 属于可靠性底线 |
| Electron E2E probes/diagnostics | 打包桌面验收和失败 artifact | D | 测试时 | 不进入生产插件目录 |

## 11. 数据与存储

| 功能/组件 | 建议形态 | 边界 | 判断 |
|---|---|---|---|

## 13. 插件化优先级清单

### P0：先守住底座边界

- [ ] 为除已接通的 `tool-presentation`、`model-router` 外的 5 个 Required manifest 分别定义最小宿主接口、生命周期、health、dispose、状态迁移和失败矩阵。
- [ ] 明确 `AgentEngine` 在组件图中的 replacement group，并把 PI engine/subagent/provider adapter 的归属写进契约。
- [ ] 固化所有组件必须经过的 permission、security、PathGuard、trace、abort 和事件终态链，禁止扩展点覆盖。
- [ ] 为组件 package 建立 manifest schema、签名/来源、版本兼容、权限声明、资源上限和安装隔离格式。
- [ ] 提供不依赖桌面 pane 的恢复入口：CLI 可列出、禁用、回滚组件，并恢复内置 Required provider。

### P1：先插件化边界清楚的可选能力

- [ ] 将 21 个内置 Agent 工具改为按工具包 manifest 注册，保持现有 ToolRegistry/ToolPool/ToolPresentation 链不变。
- [ ] 将 MCP server 映射为 O 组件实例，host 与 server/tool 子贡献分层，兼容现有配置和 trust store。
- [ ] 将六种模型协议 adapter 改为 O 组件，Provider/模型配置继续作为数据。
- [ ] 建立 UI pane/settings/language-service contribution API，先迁移 Search、Git、MCP、Problems 和 TypeScript 服务。
- [ ] 将 Skill、子 Agent、Profile 统一为声明式组件资源，复用 catalog/trust/enabled/source/generation 字段，但不加载任意 JS。

### P2：扩展 Agent 与桌面宿主

- [ ] 将 prompt section、event renderer、attachment/preview provider 做成受限贡献点。
- [ ] 收窄 AgentRuntime 和 ServerContext，使插件只拿到声明过的能力句柄，不拿全局 runtime/context。
- [ ] 将 route registry 改成带权限、prefix、body limit、超时和 dispose 的受控贡献注册表。
- [ ] 定义 desktop host、window type 和 server-binding strategy 契约；所有替换在窗口重建或进程重启边界完成。
- [ ] 研究 Creator 管理 Profile：只创建/验证草稿和组合已有能力，不能静默信任、启停、替换或发布组件。

### P3：成熟后再做

- [ ] 第三方可执行组件的独立 worker/process sandbox、IPC schema、CPU/内存/网络/文件配额和崩溃隔离。
- [ ] 组件自己的扩展点采用 namespaced child contributions；由父组件维护语义，底座只治理资源、信任、生命周期和依赖图。
- [ ] 组件市场、升级通道、依赖求解、兼容矩阵、回滚历史和供应链审计。
- [ ] 在已有两个以上真实实现且替换收益明确后，再考虑 backup、HTTP client、内部 parser 等低优先级模块的插件协议。

## 14. 明确不做的事

- 不把每个源文件、类、函数、HTTP endpoint、按钮或模型条目包装成插件。
- 不允许“万物皆插件”演变成“万物皆可热替换”；状态、进程和安全边界决定真实切换时机。
- 不允许普通 Agent 看见完整管理面或调用信任、卸载、Required 替换接口；它只看当前 Profile 投影出的工具和提示词。
- 不允许插件依赖具体 provider ID；依赖必须指向 capability、contract version 和 replacement group。
- 不允许 UI 插件直接访问 Node/Electron、配置目录或密钥；必须通过版本化宿主 API。
- 不允许插件自定义权限结果、伪造 trace/成功终态、修改历史事件或绕过 session generation 固定。
- 不让“插件的插件”各建一套插件系统。父组件可声明 namespaced 扩展点，子贡献仍登记到同一底座，并受统一信任、依赖、资源和卸载检查。
- 不把开发测试脚本和生产组件装载混在同一目录、manifest 或权限模型中。

## 15. 验收口径

一项能力只有同时满足以下条件，才可标记为“已组件化”，而不是“已有清单项”或“代码已拆模块”：

- [ ] 有稳定 manifest、唯一 ID、版本、来源、kind、capability 和依赖声明。
- [ ] 有窄宿主接口；实现不读取全局 runtime、ServerContext 或 Electron 对象。
- [ ] 有 trust、enable/disable、health、dispose 和失败终态。
- [ ] Required Component 有健康替代者检查、隔离预检、用户批准、原子提交、generation lease 和回滚。
- [ ] Optional Component 卸载后不残留工具、路由、事件订阅、worker、子进程、窗口或持久锁。
- [ ] Agent 可见性来自 Profile 投影；权限和证据约束不会因组件切换而消失。
- [ ] live/replay/refresh/fork 对组件 generation 和最终状态解释一致。
- [ ] 有单元、集成、跨层、失败矩阵和打包桌面验收；安全关键替换另有 shadow 对比。
- [ ] 有 CLI 恢复路径，桌面组件或第三方组件崩溃时仍可回退到内置 Required provider。
- [ ] 文档和生成 catalog 与运行时注册真源一致。
