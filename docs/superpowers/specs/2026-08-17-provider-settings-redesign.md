# 模型厂商设置页重设计

日期：2026-08-17

## 1. 背景

现有“设置 > 模型”同时展示全部官方厂商、认证状态、模型列表和完整自定义厂商表单。用户即使只使用一两个厂商，也必须先扫描所有官方条目；自定义厂商的 Provider ID、协议、模型发现路径、价格和 JSON 参数又与常用连接字段处于同一视觉层级。

本次重设计参考 `example/cc-switch-main` 的“已添加厂商列表 + 独立添加流程”，但不照搬大尺寸卡片、第三方中转预设或视觉皮肤。目标是让日常模型切换保持紧凑，让新增中转服务通常只需填写 3 至 4 项，同时保留现有高级能力和安全边界。

## 2. 目标

- 主页面只呈现用户实际使用的厂商，不让未配置官方厂商长期占位。
- 厂商状态、当前模型和切换操作在一屏内清楚可见。
- 添加、编辑与日常切换分层，不在一个页面摊开所有字段。
- 普通 OpenAI/Anthropic 兼容中转不要求用户先理解内部 Provider ID 和六种协议名称。
- 保持现有配置格式、秘密存储、revision 并发控制、引用检查和同源限制。
- 在 Electron 最小窗口宽度和浅色/深色主题下保持可用。

## 3. 非目标

- 不新增或推荐第三方中转服务。
- 不改变 PI 官方厂商、认证和模型注册语义。
- 不改变 `CustomProviderDefinition`、`ModelDescriptor`、秘密文件或 revision 格式。
- 不增加厂商图标上传、远程图标下载或图标裁剪存储。
- 不自动进行网络探测；连接测试和模型发现仍由用户明确点击触发。
- 不重做聊天区模型选择器。

## 4. 信息架构

“设置 > 模型”包含三个互斥视图：

1. 厂商列表：日常查看状态和切换模型。
2. 添加厂商：选择官方厂商或自定义 API 模板。
3. 厂商编辑：配置连接、认证和模型，高级字段默认折叠。

视图在同一个设置内容区内钻取，不叠加新的模态框。添加和编辑页左上角提供返回按钮；离开编辑页时取消仍在进行的 reveal、测试和模型发现请求。

## 5. 厂商列表

### 5.1 可见范围

主列表只显示：

- 已配置的官方厂商，包括 API Key、OAuth 或 PI 能确认可用的其他认证方式。
- 所有已保存的自定义厂商；`authMode: none` 视为已配置。
- 当前模型所属厂商，即使认证快照暂时未完成，也不得在刷新期间从列表闪退。

未配置官方厂商只出现在“添加厂商”视图。首次进入且没有任何可见厂商时，显示空状态和单一“添加厂商”命令，不自动打开复杂表单。

### 5.2 卡片布局

桌面宽度使用紧凑双列卡片，窄窗口降为单列。每张卡片包含：

- 本地图标或自定义文字标识。
- 厂商显示名称。
- 连接状态和当前厂商标识。
- API 域名，不显示完整带查询参数的 URL。
- 官方/自定义、协议摘要和模型数量。
- 模型下拉框。
- “使用”按钮。
- 图标式编辑按钮及 tooltip。

选择下拉框只改变卡片内的待选值；点击“使用”后才调用现有模型切换接口，避免误触。点击卡片空白区域不切换模型、不进入编辑。

当前模型在列表顶部以紧凑状态栏展示，并在所属卡片上使用克制的强调边框。卡片不展示 API Key 内容、模型高级参数或删除按钮。

### 5.3 图标

- 官方厂商使用随应用打包的本地图标，不运行时访问网络。
- 图标资源必须有可核实的许可；无法确认许可时使用项目自有的简化文字标识。
- 自定义厂商根据显示名称生成最多两个字符的稳定文字标识。
- 厂商名称始终可见，图标不能成为唯一信息来源。

## 6. 添加厂商

### 6.1 官方厂商

官方厂商列表来自当前 PI runtime 提供的官方基线，不在前端维护另一份能力清单。已配置且已在主列表显示的官方厂商可标记“已添加”，但仍允许进入认证编辑。

选择官方厂商后进入官方认证页，继续复用现有 `/api/auth`、`/api/auth/reveal` 和模型加载路径。本批不把官方厂商转换为自定义配置。

### 6.2 自定义 API 模板

只提供三类入口：

- OpenAI 兼容：默认协议为 `openai-completions`。
- Anthropic 兼容：默认协议为 `anthropic-messages`。
- 其他协议：在进入编辑页后选择 OpenAI Responses、Mistral Conversations、Azure OpenAI Responses 或 PI Messages。

不内置任何第三方中转站名称、地址、价格或 API Key 获取链接。

## 7. 厂商编辑

### 7.1 常用配置

默认展开区域只显示：

- 厂商名称。
- API 地址。
- API Key；无认证模式时显示明确开关而非空 Key 输入框。
- 模型 ID 和可选显示名称。
- “获取模型”“添加模型”操作。

底部固定操作栏包含测试连接、保存，以及编辑已保存自定义厂商时的删除命令。删除仍沿用二次确认和引用占用提示。

### 7.2 Provider ID

新建时根据厂商名称生成候选 ID：转小写、连续非 ASCII 字母数字折叠为连字符、去除首尾连字符。结果为空时使用 `custom-provider`；与官方或自定义 ID 冲突时，按现有 ID 集合选择第一个可用的递增候选，例如 `custom-provider-2`、`custom-provider-3`。用户可在高级设置中保存前修改。

高级设置中的标签使用“厂商 ID（内部标识）”，并说明“用于配置引用，保存后不可修改”。保存后的 ID 继续只读。后端仍是最终校验者，前端生成不能替代现有重名和格式校验。

### 7.3 模型发现

模型发现仍由用户点击“获取模型”触发，不在输入 Base URL 时自动联网。

OpenAI 兼容模板在没有显式 `modelDiscovery` 时，按以下规则生成本次请求的候选路径：

- 将 Base URL 路径末尾规范为单个 `/`。
- 在规范后的路径后追加 `models`。
- 例如 `https://api.example.com/v1` 和 `https://api.example.com/v1/` 均得到 `https://api.example.com/v1/models`。

候选值只用于本次请求；发现成功并经用户确认导入后，才把对应相对路径写入当前草稿。发现失败不修改草稿、不保存配置，并提示用户手动填写模型 ID，或在高级设置中修改“模型发现路径”。

Anthropic 兼容和其他协议不假设存在 OpenAI 模型列表；未配置发现路径时，“获取模型”提示需要在高级设置中填写同源模型列表路径。

所有发现请求继续满足现有约束：同源 HTTP(S)、手动触发、携带当前内存凭据、拒绝重定向、15 秒超时、64 KiB 响应上限、只解析 OpenAI-compatible `{ data: [{ id }] }`，且测试/发现不得持久化秘密或配置。

### 7.4 高级设置

默认折叠以下字段：

- 厂商 ID。
- 底层协议。
- 认证模式。
- 自定义 Headers。
- 模型发现路径。
- 上下文窗口、最大输出、推理与图片输入能力。
- USD/million tokens 价格。
- Sampling JSON 和 Compatibility JSON。

展开高级设置不改变字段值。后端字段级错误必须重新展开对应区域，并把焦点移到准确控件。

## 8. 状态与错误处理

- 列表、添加和编辑各自拥有 generation；旧请求不得覆盖新视图。
- 保存和删除继续以服务端返回的 revision 为唯一权威，冲突后刷新最新 revision，同时保留未保存输入。
- 官方认证加载失败时，自定义厂商列表仍可用；自定义快照或 capabilities 加载失败时，官方厂商仍可用。
- 连接测试和模型发现只锁定各自按钮，不冻结整个设置页。
- 返回列表时中止仍在进行的测试、发现和 reveal；已提交的保存/删除继续观察最终结果。
- API Key、Header 值和可能包含秘密的错误继续经过现有脱敏边界，DOM 只使用安全文本写入。
- 空状态、加载、连接失败、未配置、revision 冲突和引用占用均提供内联状态，不依赖 toast 作为唯一反馈。

## 9. 响应式与可访问性

- 卡片网格在可用内容宽度不足时降为单列，不通过 viewport 宽度缩放字号。
- 编辑页使用单一滚动内容区和固定底部操作栏，操作栏不得覆盖最后一个字段。
- 所有图标按钮提供 `aria-label` 和 tooltip；状态不能只靠颜色表达。
- 添加模板、厂商卡片、模型选择和高级设置可使用键盘操作，并有明确 focus-visible 样式。
- 长厂商名、域名和模型 ID 使用省略显示并提供完整 title，不挤压按钮。
- 深色与浅色主题均复用现有 CSS 变量，不引入只适用于单一主题的硬编码背景。

## 10. 组件边界

保持现有 `SettingsProviderModelController` 作为设置页模型入口，但将视图职责拆为：

- ProviderCardList：过滤、空状态、当前模型摘要和卡片事件。
- ProviderPicker：官方厂商与三个自定义模板入口。
- OfficialProviderEditor：现有官方认证和模型行为的独立视图。
- SettingsCustomProviderEditor：保留草稿、秘密、revision 和网络操作，改为常用/高级两层渲染。
- ProviderIdentity：官方本地图标和自定义文字标识的纯展示组件。

这些组件通过显式回调切换视图，不新增 `App.*` 全局引用。后端 API 和项目 contract 保持不变；模型发现默认 URL 的推导应放在项目自有、可独立测试的纯函数中。

## 11. 测试

### 11.1 前端

- 未配置官方厂商不出现在主列表，已配置官方和已保存自定义厂商出现。
- 零厂商时显示空状态，不自动进入编辑器。
- 卡片模型下拉不会立即切换，点击“使用”提交准确的 `(providerId, modelId)`。
- 添加、编辑和返回的视图切换不泄漏旧请求或旧草稿。
- Provider ID 自动生成、冲突后缀、保存前可改和保存后只读。
- 常用字段默认可见，高级字段默认折叠；高级字段错误自动展开并聚焦。
- OpenAI Base URL 的 `/models` 候选推导覆盖有/无尾斜杠和非根路径。
- 官方图标和自定义文字标识均有可访问名称。
- 双列/单列响应式门禁，长名称和模型 ID 不覆盖操作按钮。

### 11.2 服务端与契约回归

- 现有自定义厂商 CRUD、测试连接、模型发现、reveal、引用检查和 revision 测试保持通过。
- 默认发现路径仍经过现有同源、重定向、超时、响应上限和脱敏测试。
- 官方 `/api/auth`、`/api/auth/reveal`、`/api/models` 和模型切换回归保持通过。
- XSS sink 门禁和设置页无 inline handler 门禁保持通过。

### 11.3 手工验收

1. 无认证的新环境进入模型页，只看到空状态。
2. 添加官方 DeepSeek，保存 API Key 后出现带官方图标的卡片。
3. 添加 OpenAI 兼容中转，仅填写名称、Base URL、Key，获取并导入模型后保存。
4. 在两张卡片间切换模型，确认选择下拉本身不触发切换。
5. 编辑自定义厂商，确认高级设置折叠、ID 只读、测试与保存可用。
6. 在最小窗口宽度、浅色主题和键盘操作下完成上述流程。

## 12. 成功标准

- 常用中转配置首屏不超过四类输入。
- 未配置官方厂商不占主列表空间。
- 日常切换模型无需进入编辑页。
- 所有现有安全、秘密、revision 和引用语义保持不变。
- 全量类型检查、unit、routes、frontend 和 CSS 门禁通过。
