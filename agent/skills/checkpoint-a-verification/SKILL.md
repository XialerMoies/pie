# Checkpoint A Verification

这是一个仅用于 Checkpoint A 验收的测试技能。它要求先读取事实来源，再给出可复核结论；不能只根据用户描述、缓存印象或 Agent 自己的声明下结论。

## 必须执行

1. 明确本次检查对象：skill、user memory、workspace memory，或它们的状态变化。
   如果对象只是一般项目文件、能力目录或其他不属于上述范围的内容，先说明“本技能不适用”，不要强行套用本技能或推断项目能力是否缺失。
2. 使用当前 Agent 已有的只读工具读取实际来源：
   - skill：读取对应的 `SKILL.md`，并检查设置页/API 返回的 trust、enabled、parse 状态；
   - memory：先用 `list_memory` 查看索引摘要，需要确认正文时再用 `read_memory`；
   - workspace：同时记录当前 workspace，不能把其他 workspace 的结果当作当前结果。
3. 只报告实际观察到的事实。没有读取到的内容必须标记为“未验证”，不能推测。
4. 输出以下四个部分：
   - `对象与范围`：检查了什么、在哪个作用域；
   - `证据`：读取了哪些文件、工具结果或状态字段；
   - `结论`：通过、失败或未验证，并说明原因；
   - `残留风险`：例如内容已修改、作用域不明、没有版本历史。
5. 最后一行必须包含：`CHECKPOINT_A_EVIDENCE_V1`。这个标记只证明本技能的报告格式已执行，不能替代上面的事实证据。

## 证据硬门槛

“证据”只指工具成功返回的事实载荷，不是调用记录。每条结论都必须能回指到同一条工具结果中的字段或原文。

- `IN`、`input`、工具名、工具描述、请求参数、路径回显、技能正文、系统提示、缓存印象和模型记忆都不是读取证据。
- `file_read` 只有返回文件正文（或明确的结构化读取错误）才算完成读取。只看到 `path` 不能证明文件存在、可读、大小、修改时间或任何内容。
- `explorer_list` 只有返回目录项 `items`/等价目录载荷（或明确的结构化错误）才算完成列目录。只看到请求目录不能证明目录内容。
- 设置页/API 状态必须在同一对象、同一作用域的返回载荷中逐字段观察到 `trust`、`enabled`、`parse`。缺失字段一律写“未验证”，不能从技能列表或上下文标签补齐。
- 工具失败、返回空壳、只回显入参、输出被截断到所需字段之前或结果含义不明确时，结论只能是“未验证”；不得写“通过”、不得补写预期内容。
- 证据项至少记录：工具名、请求对象/作用域、实际返回字段或原文摘录。无法提供三者之一时，该项不是证据。

## 限制

- 不修改 skill、memory、索引或项目文件；除非用户明确要求执行验收中的写入、禁用、删除或修正动作。
- 不把“技能名称出现在上下文”当作技能真正生效；必须说明它是否改变了实际检查步骤或结果。
- 不把“记忆出现在列表”当作 Agent 已正确使用；必须给出读取正文或实际回答中的对应事实。
- 宿主当前可用的工具不等于项目能力目录中的运行时工具；判断目录是否缺失前必须确认目录的声明范围。
- 当前系统没有内建的记忆版本历史。没有备份证据时，回滚只能报告为未验证或未实现。
